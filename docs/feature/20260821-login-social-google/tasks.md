## Critérios de aceite

- **TASK-357**: `backend/routes/api.php` ganha `Route::get('/auth/google/login', [GoogleAuthController::class, 'loginRedirect']);` fora do grupo `jwt.auth`, ao lado de `GET /auth/google/callback`. Novo método `loginRedirect()` em `GoogleAuthController` grava `Cache::put('google_oauth_state:'.$token, ['intent' => 'login'], now()->addMinutes(self::STATE_TTL_MINUTES))` com `$token = Str::random(40)` e devolve `redirect()->away(...)` para a URL do Socialite (`stateless()->with(['state' => $token])->redirect()->getTargetUrl()`) — **não** JSON (diferente de `redirectUrl()`). `./vendor/bin/pint --test app/Http/Controllers/GoogleAuthController.php` limpo.

- **TASK-358**: novo teste em `GoogleAuthControllerTest.php`: `$this->get('/api/auth/google/login')` com config de `services.google.*` de teste (mesmo padrão de `test_redirect_url_returns_a_google_authorize_url_with_opaque_state`) resulta em redirect (`assertRedirect` com prefixo `https://accounts.google.com/o/oauth2/auth` — usar `assertStatus(302)` + parse do header `Location`, já que `assertRedirect` exige URL exata) e o `state` da URL de redirect existe no cache com `['intent' => 'login']` (sem `user_id`, diferente do state de `link`). `php artisan test --filter=GoogleAuthControllerTest` verde.

- **TASK-359**: em `GoogleAuthController::callback()`, o fetch `Socialite::driver('google')->stateless()->user()` (hoje só dentro do branch `intent === 'link'`) passa a rodar uma vez, logo após validar o `state`, com o `try/catch` existente cobrindo os dois intents. Branch `$state['intent'] === 'login'` chama novo método privado `handleLoginCallback(SocialiteUser $googleUser, string $frontendUrl)`: `User::where('google_id', $googleUser->getId())->first()` senão `User::where('email', $googleUser->getEmail())->first()` senão `User::create([...])` (`password: null`, `email_verified_at: now()`, `google_id`, `avatar_url`, `name`, `email`); se achou por e-mail, atualiza `google_id`/`avatar_url`/`email_verified_at` (se ainda nulos) antes de salvar; `QueryException` no save vira log + `redirect()->away("{$frontendUrl}/login?google_error=1")` (mesmo padrão do branch `link`). Sucesso: `$token = auth('api')->login($user)`, gera `$code = Str::random(40)`, `Cache::put('google_login_code:'.$code, $token, now()->addMinutes(1))`, `redirect()->away("{$frontendUrl}/login?google_code={$code}")`. Falha do Socialite para este intent redireciona para `"{$frontendUrl}/login?google_error=1"` (log com prefixo `[google-login]`, não `[google-link]`). `./vendor/bin/pint --test app/Http/Controllers/GoogleAuthController.php` limpo.

- **TASK-360**: novos testes em `GoogleAuthControllerTest.php` (helper novo `loginState()`, mesmo padrão de `linkState()` mas com `['intent' => 'login']`, sem `user_id`):
  - Usuário novo: nenhum `ex_users` com o e-mail/`google_id` do Google fake → `callback` redireciona para `http://localhost:3000/login?google_code=` + 40 chars, e `assertDatabaseHas('ex_users', ['email' => ..., 'google_id' => ..., 'password' => null])` com `email_verified_at` não nulo.
  - Auto-vínculo: `User::factory()->create(['email' => 'ana@example.com', 'google_id' => null])` já existe com o mesmo e-mail do Google fake → `callback` não cria segunda linha (`assertDatabaseCount('ex_users', 1)`), e a linha existente passa a ter o `google_id` do fake.
  - Login repetido: usuário já tem `google_id` igual ao do fake → `callback` reaproveita esse usuário (`assertDatabaseCount('ex_users', 1)`), token emitido é válido para ele (`auth('api')->setToken($token)->user()->id === $user->id` a partir do `access_token` implícito, ou decodificar via `Cache::pull` do código e validar o JWT).
  - Erro: `Socialite::fake('google')` configurado para lançar (usar um double/spy que joga exception, mesmo padrão do teste de vínculo que cobre falha do Socialite) → redirect para `http://localhost:3000/login?google_error=1`.
  - Ajuste do teste **existente** `test_callback_returns_501_when_intent_is_not_link`: trocar `'intent' => 'login'` por `'intent' => 'bogus'` no `Cache::put` do teste — sem isso, ele quebraria com esta feature (intent `login` deixa de cair no 501). `php artisan test --filter=GoogleAuthControllerTest` verde, incluindo o teste ajustado.

- **TASK-361**: novo método `GoogleAuthController::exchangeLoginCode(Request $request)` e rota pública `Route::get('/auth/google/exchange', [GoogleAuthController::class, 'exchangeLoginCode']);` (fora de `jwt.auth`, ao lado de `callback`). `Cache::pull('google_login_code:'.$request->query('code'))`; se `null`/ausente, `response()->json(['message' => 'Código inválido ou expirado.'], 401)`; se presente, `response()->json(['access_token' => $token, 'token_type' => 'bearer', 'expires_in' => auth('api')->factory()->getTTL() * 60])`. `./vendor/bin/pint --test app/Http/Controllers/GoogleAuthController.php` limpo.

- **TASK-362**: novos testes em `GoogleAuthControllerTest.php`: (1) `Cache::put('google_login_code:'.$code, $jwt, ...)` manual + `getJson('/api/auth/google/exchange?code='.$code)` → `200` com `access_token === $jwt` e `token_type === 'bearer'`; (2) código nunca gravado ou expirado → `401` com a mensagem esperada; (3) uso único — repetir a mesma chamada do caso (1) uma segunda vez → `401` na segunda. `php artisan test --filter=GoogleAuthControllerTest` verde.

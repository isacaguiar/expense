## 1. Desvios do fluxo padrão / pendências

Feature de infra (CI). Verificação da TASK-233 = parse de YAML + `git diff` no escopo; sem suíte automatizada que exercite deploy. Sem backend PHP nem frontend tocados. TASK-234 é 100% execução humana (probe, chaves, secrets).

**`public/.htaccess` / versão de PHP:** o `public/.htaccess` do host só tinha o comentário `# php -- BEGIN cPanel-generated handler` ("herda o pacote PHP", sem diretiva). O `rsync` sobrescreveu com o `backend/public/.htaccess` do repo (rewrite do Laravel). PHP servido = **8.2.33** (confirmado no host, `php -v` + `php artisan --version` → Laravel 10.48.29) — compatível, sem erro de versão. Ressalva mantida: se a versão de PHP for fixada no *MultiPHP Manager*, o cPanel injeta `AddHandler …ea-phpXX` nesse mesmo arquivo e o deploy seguinte apaga; nesse caso o bloco tem que ir pro `backend/public/.htaccess` versionado.

**`storage/` no host (correção 3 em §2):** o build **e** o `EXCLUDE` do rsync tiram `storage/logs`, então essa pasta nunca era criada no host → 1º deploy serviu **HTTP 500** (Laravel sem onde logar). Corrigido com `SCRIPT_AFTER` na action (`mkdir -p storage/logs storage/framework/{cache/data,sessions,views} bootstrap/cache` + `chmod` + `optimize:clear` + `config:cache`/`route:cache` no host). O passo runner "🧠 Gerar caches Laravel" foi **removido** — cacheava com caminhos do runner (`/home/runner/...`), inválidos no host; agora o cache é feito no destino via `SCRIPT_AFTER`.

**Verificação do 1º deploy verde** (2026-09-01): passo "Deploy via SSH (rsync)" conclui sem `ECONNREFUSED` / sem `Permission denied`; `/home1/isacag00/novemax/expense/api/` com `artisan`, `.env`, `composer.json`, `public/index.php`, `bootstrap/cache/config.php` (todos `Aug 31 23:46`); `storage/app/` intacto (`Aug 29 08:37` — `--delete` respeitou o `EXCLUDE`; ainda sem `comprovantes/` porque o backend nunca rodou em prod antes); `curl -sSI https://expense-api.novemax.com.br` → **HTTP 200**, cookies `XSRF-TOKEN`/`scd_session` (Laravel de pé).

**Pendências fora do PR desta feature:**

1. **`00-constitution.md` §3** — a linha "Deploy backend | GitHub Actions → FTP (`scd.novemax.com.br`)" fica desatualizada; passa a "GitHub Actions → SSH/rsync (porta 2222)". Editar a Constitution é **gate humano** (§5.2) → diff aprovado à parte, com bump de `Versão`/data. Não entra no PR da feature.
2. **`deploy-site.yml` e `deploy-frontend.yml`** ainda usam `SFTP_HOST`/`SFTP_USER`/`SFTP_PASS` → **não** remover esses secrets agora. A rotação de `SFTP_PASS` (esteve em texto puro nos deploys anteriores ao `ftps`, pendência aberta no BFF `20260829-deploy-backend-ftp-texto-puro.md`) segue como gate 100% humano.
3. **`php artisan key:generate` no runner** sobrescreve o `APP_KEY` vindo de `secrets.ENV_APP_KEY` por uma chave aleatória a cada deploy — quirk pré-existente do workflow, não tocado aqui. App sobe (qualquer chave válida serve), mas dado cifrado com a chave "real" não é legível. Avaliar remover esse passo num follow-up.
